# European Small/Mid-Cap Value Shortlist

A value-investing dashboard that screens ~6,109 raw European small/mid-cap
companies (US$15M–1B market cap) down to a ranked top-150 shortlist using a
documented 9-dimension scoring system ("v6"), and keeps that shortlist live
by periodically refreshing market caps (and eventually gross margins) for
the companies in it.

Full background, the scoring model, and open items are in
[`docs/handoff-brief.md`](docs/handoff-brief.md) — read that first.

## Dashboard

The dashboard is now a **plain static HTML file with no server, no
database, and no dependency on claude.ai** — `docs/index.html`, built from
the data in this repo. It's self-contained: open it directly in a browser,
or host it anywhere that serves static files.

- `dashboard/index.html` is the original claude.ai Artifact version (kept
  as a historical backup — see `dashboard/README.md`). It's no longer the
  one being developed.
- `docs/index.html` is the current version, generated by
  `scripts/build_site.py` from `site/template.html` +  `data/*.json`. All
  1,000 companies' financials are embedded at build time; there's nothing
  to fetch at runtime.
- In-browser edits (typing a market cap, pasting a bulk update) recompute
  scores live and persist to that browser's `localStorage` only — they are
  **not** shared between devices or visitors. That's the trade-off for
  having no backend and no ongoing hosting cost. See "Publishing a real
  update" below for how a change becomes permanent for everyone.

### Publishing it live

The dashboard is hosted on **Cloudflare Workers** (static assets), private
behind **Cloudflare Access** — a login page (email + one-time code) gates
it, so only approved email addresses can view it. No server to maintain,
no recurring cost (Cloudflare's free tier covers this; Access is free for
up to 50 users).

- `wrangler.jsonc` at the repo root points a git-connected Cloudflare
  Workers project at `./docs` as its static asset directory — that's what
  Cloudflare's "Connect to Git" deploy flow reads.
- Access is configured directly on the Worker: **Settings → Domains &
  Routes → workers.dev → Protect this Worker behind Access**, scope **All
  traffic**, with an Allow policy listing the approved email(s).
- We initially also published a public copy via GitHub Pages
  (`/docs` on this branch) to prove the static rebuild worked with zero
  claude.ai dependency; that's now disabled (Settings → Pages → Source →
  None) since Cloudflare + Access is the actual private, permanent home.

## Workflow

**Local preview / manual rebuild:**
```
pip install -r requirements.txt
python3 scripts/build_site.py      # -> docs/index.html
python3 -m http.server 8000 -d docs   # open http://localhost:8000
```

**Publishing a real update** (market cap or gross margin, for everyone —
not just a local browser edit):

1. Edit `data/mc_overrides_applied.json` (or `data/gm_overrides_applied.json`)
   with the new value(s) and a source.
2. Run `python3 scripts/snapshot.py` to save a dated pre-update record into
   `snapshots/`.
3. Commit and push. The **Auto-rebuild** GitHub Action regenerates
   `docs/index.html` and commits it automatically — or run
   `python3 scripts/build_site.py` yourself and commit `docs/index.html`
   if you'd rather not wait for CI.

## Auto-rebuild

`.github/workflows/build-site.yml` runs on every push that touches
`data/**`, `site/**`, or the build scripts, regenerates `docs/index.html`,
and commits it back — so the published dashboard never falls out of sync
with the data files, without anyone needing to remember the manual step
(or needing Claude in the loop at all).

## Source-rule constraints

Gross-margin research must come only from company-published documents and
exchange filings (annual reports, IR pages, earnings releases, exchange
filings) — no third-party aggregators. No manual additions or removals to
the final ranked list; if a company is missed, refine the model instead.
See `docs/handoff-brief.md` for the full detail and the one standing
exception (Card Factory).
